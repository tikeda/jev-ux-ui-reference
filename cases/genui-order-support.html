Generative UI／注文サポート

Flutter/GenUI order-support prototype

注文の追跡や返品を言葉で頼むと、必要な画面部品とフォームがその場で組み立てられるサポートアプリの試作

判断型Choice推定 根拠公開投稿のみ

このUIがしていること

依頼に応じて画面が組み変わるが、返品のように結果を伴う操作では、利用者がフォームに入力し、完了の確認を受け取る段階が残されている。判断が選ぶのは「どの部品を出すか」までで、操作の実行は利用者の明示的な入力を経る。

  • 部品は決まった候補の中から選ばれる、と作者は説明している。自由に画面を生成するのではなく、用意された部品を出し分ける形である。
  • 返品の前にフォームが出て、後に「Demo return saved」の確認が出る。何が起きたかを、利用者が文字で確かめられる。
  • 下端の表記が、デモであることとJevを使っていることを示す。
  • 意図と違う部品が出たときにどう直すかは、動画からは分からない。

キャプチャ

見る箇所掲載した画像は「画面キャプチャ未取得」の告知で、製品の画面ではない。動画で見る箇所は、注文一覧から注文の詳細・配送の追跡・返品フォームへ移る流れ、「Demo return saved」の確認、下端の「Powered by Jev + GenUI」の表記

入力から画面の変化まで

  1. 判断への入力

    利用者が入力する依頼文。監査の記録では、注文の追跡を頼む文や、バックパックの返品を頼む文が使われている。

  2. Jevの判断

    作者の説明では、依頼に対して表示する画面部品をJevが選ぶ。候補の部品の一覧、確率、選択の記録は動画に出ていない。

  3. 結果がUIをどう変えるか

    監査の記録では、「KIN / care」というサポートアプリが、注文一覧から、生成された注文の詳細、配送の追跡、返品フォームへ進み、最後に「Demo return saved」の確認が出る。

判断型の見立て
Choice推定
依頼に応じて画面部品を選ぶという作者の説明からの見立て。調査で確認された動画にも、Jevの出力や質問型は出ていない。

Jevとの適合

依頼文から、限られた部品の中のどれを出すかを選ぶ判断は、Jevの低遅延に合う。作者の投稿は、部品の選択が手元で動いているように感じる速さを主眼にしている。ただし、選択の過程は画面に出ておらず、どこまでがJevの判断かは作者の説明に頼っている。

確認範囲と未確認事項

作者による投稿動画が根拠で、内容は調査監査（2026-09-21）の確認記録による。動画はこのサイトでは保存しておらず、画面は掲載していない。公開されたビルドやリポジトリはない。動画には確率や部品選択の記録が出ておらず、部品を選ぶのがJevだというのは作者の説明である。最後の返品はデモ用の操作で、実際の返金や発送ではない。

  • 確認済み調査監査（2026-09-21）が動画で確認した範囲。注文一覧から注文の詳細、配送の追跡、返品フォーム、「Demo return saved」の確認へ進む流れと、下端の「Powered by Jev + GenUI」とデモである旨の表記。このサイトの作業では動画を再確認していない
  • 未検証Jevへの入力と出力、部品の候補、確率、意図と違う部品が出たときの直し方、公開ビルドとリポジトリの有無、実際の注文データでの動作
  • 推定扱い質問型（Choiceと見立て）。部品を選ぶという作者の説明からの見立てで、画面には質問型が出ていない
  • 引用投稿の動画と画面は掲載していない。掲載した画像はこのサイトで作成した告知で、製品の画面ではない
